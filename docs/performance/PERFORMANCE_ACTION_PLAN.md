# FOX & HEMA ERP — Performance Action Plan

This plan follows the Phase 0 baseline in [PERFORMANCE_BASELINE.md](./PERFORMANCE_BASELINE.md). It is a proposed sequence, not authorization to touch production or to alter business behavior. No implementation is included in this document.

## Execution guardrails

- Use only an approved disposable/local MySQL or MariaDB schema and isolated Redis namespace. Confirm endpoint and schema ownership before running any profiler or fixture setup.
- Do not use production, shared development data, or shared Redis. Do not migrate, seed, reset, flush, post, or create authenticated browser sessions outside the approved fixture.
- Record per-request and per-Livewire measurements independently. Run three samples for each case and report median plus range; keep Debugbar state, actor, permissions, location, page state, dataset, and cache state identical in each pair.
- Do not run full PHPUnit. Existing performance test bootstraps may create/drop schemas; inspect their selected configuration and ensure the test database is disposable before executing them.
- Do not add indexes, cache authorization decisions, or weaken locks/ownership checks without measured evidence and correctness tests.

## Recommended order and gates

1. **P1-01 first.** Do not use historical figures as current acceptance targets.
2. Run P1-02 and P1-03 as separate investigations; do not combine authorization and cache correctness changes.
3. Select only the highest-cost remaining module path after the new profile. P1-04 through P1-07 are independent workstreams and should be separate pull requests.
4. Perform P1-08 only for measured option-growth or validated namespace risk.
5. P1-09 and P1-10 are gated: validate deployment cache namespaces separately, and do not consider an index until a query plan justifies it.

Each implementation should be reviewed independently, with focused tests and a before/after profile from the same isolated dataset and request context. No task authorizes a production change, dependency installation, commit, push, or deployment.
